# Data Model: Категории и подкатегории

## Category

- `id`: целое, ключ
- `name`: непустой текст после обрезки пробелов. Повтор разрешён (`Category.name`)
- `created_at`: время создания, правкой имени не меняется

## Subcategory

- `id`: целое, ключ
- `name`: непустой текст. Повтор разрешён, в том числе внутри одной категории (`Subcategory.name`)
- `category_id`: ровно одна существующая категория (`Subcategory.category_id`)
- `created_at`: время создания

Перенос меняет только `category_id`. Товары подкатегории не переписываются.

## Item (существующая сущность)

Прежние поля без изменений: `name`, `price`, `photo_file_id`, `status`, `created_at`.

Новые поля:

- `category_id`: категория прямой привязки или пусто (`Item.category_id`)
- `subcategory_id`: подкатегория или пусто (`Item.subcategory_id`)

Ограничения:

- Новый товар: заполнено ровно одно из двух полей, и цель существует.
- Старый товар: оба поля пустые, пока админ не привяжет.
- Оба поля сразу заполнены быть не могут.
- Скрытый товар (`status = hidden`) не меняет привязку, как и остальные правки.
- `created_at` при смене имени, цены, фото и привязки не меняется.

## Видимость в каталоге

В списках каталога только `status` `available` и `pending`, как раньше.

- Корень: все категории по имени.
- Категория: её подкатегории по имени и товары с этой `category_id` и пустой `subcategory_id`, по `created_at` убыванию.
- Подкатегория: товары с этой `subcategory_id`, по `created_at` убыванию.
- Без категории: товары, у которых оба поля пустые. Вход есть только если такие видимые товары есть.

## Что не хранится

Отдельной записи «Без категории» нет. Удаление категории и подкатегории не входит в модель.
