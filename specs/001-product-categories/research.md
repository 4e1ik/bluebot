# Research: Категории и подкатегории

## Хранение

**Decision**: Две таблицы, `categories` и `subcategories`. У товара две nullable-колонки, заполнена ровно одна у новых строк. У старых строк обе пустые.

**Rationale**: Так прямо описаны «категория или подкатегория» и перенос подкатегории без переписывания её товаров. Одна таблица с `parent_id` позволила бы третий уровень, который запрещён.

**Alternatives considered**: Общая таблица узлов с типом. Отклонена: проще случайно создать вложенность глубже двух уровней.

## Миграция

**Decision**: `CREATE TABLE IF NOT EXISTS` для новых таблиц и `ALTER TABLE items ADD COLUMN` для уже существующей таблицы товаров. Проверка колонок через `PRAGMA table_info`, как уже сделано для `user_id`.

**Rationale**: База уже есть. Пересоздание `items` затронуло бы брони.

**Alternatives considered**: Новая база и ручной перенос. Отклонена: ломает текущий файл и брони.

## Внешние ключи SQLite

**Decision**: Внешние ключи в схеме описать, но `PRAGMA foreign_keys` не включать.

**Rationale**: Остальной код написан без включённых внешних ключей. Включение в одном соединении меняет удаление товаров и броней.

**Alternatives considered**: Включить pragma и починить все удаления. Это шире запроса.

## Сортировка имён

**Decision**: Сортировать в Python ключом `name.casefold()`, затем `id`.

**Rationale**: `COLLATE NOCASE` в SQLite не учитывает кириллицу.

**Alternatives considered**: SQL `COLLATE NOCASE`. Отклонена для русских названий.

## Каталог

**Decision**: Корень, экран категории, экран подкатегории, экран «Без категории». Карточка товара прежняя, с строкой привязки и кнопкой назад в свой список.

**Rationale**: Совпадает с ответом по дереву и с ответом оставить старые товары видимыми, не создавая категорию.

**Alternatives considered**: Плоский список. Отклонён ответом на уточнение.

## Проверка

**Decision**: Правила привязки проверять unittest на временной SQLite. Сценарий админа дополнительно пройти на запущенном боте.

**Rationale**: В проекте нет pytest. unittest есть в стандартной библиотеке. Живой бот — критерий готовности из запроса.
