# Implementation Plan: Дата выкладки товара для админа

**Branch**: `003-show-listing-date` | **Date**: 2026-11-19 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/003-show-listing-date/spec.md`

## Summary

Админ и суперпользователь видят календарный день появления товара по Минску в виде `ДД.ММ.ГГГГ`. На карточке это отдельная строка из одной даты. На кнопках товаров в категории, подкатегории и «Без категории» дата стоит в начале подписи. Пользователь из белого списка видит прежние карточку и кнопки. Нового поля нет: читается уже сохранённый момент появления, правка товара его не меняет.

## Technical Context

**Language/Version**: Python 3.11+

**Primary Dependencies**: aiogram 3, aiosqlite, python-dotenv. Часовой пояс — стандартный `zoneinfo`, как в статистике.

**Storage**: SQLite, файл `DB_PATH` (по умолчанию `data/blubot.db`). Схема товаров не меняется.

**Testing**: unittest, как в `tests/test_categories.py`

**Target Platform**: Локальный процесс Telegram-бота, long polling

**Project Type**: Telegram-бот, один пакет `bot/`

**Performance Goals**: Дата считается при сборке одной карточки или одного списка, без отдельного запроса

**Constraints**: Без новых полей и внешних сервисов. Русский интерфейс. `protect_content` сохраняется. Пометка 🆕, брони, белый список и запрет пересылки не меняются. Корзина, «Мои брони» и ожидающие подтверждения дату не показывают. `created_at` при правке не меняется. Длинная подпись кнопки сокращается с конца, дата в начале остаётся.

**Scale/Scope**: Карточка товара и три каталожных списка. Корень каталога даты не показывает, там нет кнопок товаров.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- I. Сохранять текущее поведение. Новая строка и префикс кнопки только у админа и суперпользователя. 🆕 по-прежнему считается от появления и видна всем. Правка товара не сдвигает момент появления.
- II. Каталог меняет только админ. Показ даты не даёт пользователю из белого списка действий над товаром. Суперпользователь уже проходит как админ.
- III. Не выдумывать поведение. Источник, вид `ДД.ММ.ГГГГ` по Минску, состав экранов и место даты на кнопке взяты из ответов Q1–Q3.
- IV. Существующие данные остаются пригодными. Колонка момента появления уже есть у товаров. Миграции нет, товары не скрываются.
- V. Два уровня и одна привязка. Каталог и привязка не меняются.

Нарушений, требующих Complexity Tracking, нет.
