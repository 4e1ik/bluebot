# Спецификация blubot

## Назначение

Telegram-бот каталога товаров на продажу с белым списком пользователей и ручным подтверждением брони админом.

## Роли

### Суперпользователь (`SUPERUSER_ID` / `SUPERUSER_USERNAME` из `.env`)
- Всё, что может обычный админ
- Управляет списком админов: кнопка «Админы» → добавить/удалить по `@username`
- Самого супера нельзя удалить через бота
- Уведомления о заказах **не** получает (в рассылку новинок тоже не включается отдельно — только через таблицу `admins`, если добавлен)

### Админ (таблица `admins`)
- Добавляет / редактирует / удаляет товары
- Управляет белым списком пользователей
- Получает уведомление при **«Оформить заказ»**
- Подтверждает/отклоняет заказы в «Ожидают подтверждения»
- Кнопка **«Уведомить о новинках»** → whitelist + админы (у кого есть `user_id`)

### Пользователь (в whitelist)
- Каталог (список → фото по клику), пометка 🆕 у товаров младше 7 дней с `created_at`
- Дату появления товара (`ДД.ММ.ГГГГ` по Минску) видят только админ и суперпользователь: отдельной строкой на карточке и в начале кнопки товара в категории, подкатегории и «Без категории»
- Бронирует товары в корзину (TTL 20 мин)
- «Мои брони»: оформить заказ / очистить / отменить товар
- После оформления: «Ожидайте, скоро с вами свяжутся»
- Кнопка «Помощь» с инструкцией

## Редактирование товара

На карточке (админ): **Изменить** → Фото / Название / Цена / Привязка.  
`created_at` при редактировании **не** меняется (NEW зависит только от создания).

Новый товар сохраняется только после выбора одной цели: категория или подкатегория. Если категорий нет, бот просит создать категорию и не спрашивает фото.

## Категории

Админ и суперпользователь, кнопка «Категории»:

- создать категорию
- создать подкатегорию и сразу выбрать существующую категорию
- переименовать категорию или подкатегорию
- перепривязать подкатегорию к другой категории (её товары остаются на ней)
- удалить категорию или подкатегорию, только если она пустая

Пустое название не сохраняется. Непустая запись не удаляется: бот говорит, что внутри есть товары или подкатегории. Третьего уровня нет.

## Статистика

Кнопки «Статистика заказов» и «Статистика товаров» есть у админа и суперпользователя.

- Заказ — одно оформление корзины. В отчёт попадает с первого подтверждённого товара. Дата заказа не сдвигается, поздние подтверждения увеличивают сумму и остаются в окне первой даты.
- Товар в отчёте — подтверждённая позиция со своей датой, ценой и категорией.
- Окна по календарю Минска, до текущего момента: сегодня, неделя с понедельника, две недели с понедельника прошлой недели, текущие месяц, квартал и год, всё время.
- Категория включает свои товары и товары подкатегорий. Суммы категорий совпадают со сводкой. Один заказ может войти в несколько категорий.
- Сравнение категорий и подкатегорий по числу и по сумме. Средняя за текущий календарный месяц. Если в этом месяце сумм нет, средней нет.
- Столбчатая диаграмма сумм категорий за всё время уходит фотографией, когда есть что сравнивать.

## Каталог

- Корень: категории по имени. Если есть видимые товары без привязки — вход «Без категории» (это не запись в базе)
- Категория: её подкатегории и товары, привязанные прямо к ней
- Подкатегория: её товары
- 🆕 если с создания прошло меньше 7 дней
- Админ и суперпользователь видят день появления по Минску на карточке (строка `ДД.ММ.ГГГГ` после привязки) и в начале кнопки товара. Пользователь из белого списка эту дату не видит. Корзина, «Мои брони» и ожидающие подтверждения её не показывают
- Фото — только на карточке после клика
- На карточке одна строка привязки, «← Назад» возвращает в свой список

## Рассылка новинок

- Текст: «Появились новые позиции в каталоге…»
- Только если есть товары младше 7 дней
- Нужен `user_id` (после `/start` у клиента/админа)

## Корзина и заказ

| Статус брони | Смысл |
|--------------|-------|
| `pending` | В корзине, ещё не оформлен (20 мин TTL) |
| `submitted` | Оформлен, ждёт админа |
| `confirmed` / `rejected` / `cancelled` / `expired` | Финальные |

## Protect content

Все сообщения бота с `protect_content=True` — запрет пересылки.

## Ограничения

- Без `/start` у пользователя нет `user_id` → рассылки и уведомления о заказах не дойдут
- Полный запрет скриншотов на всех клиентах невозможен
